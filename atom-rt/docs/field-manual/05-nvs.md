# 有効と NVS

経路は機体の配線図です。有効は「今この周期で触るか」です。机上では経路を残したまま、使わない軸だけ切ります。

## チェックの意味

| 操作 | 残るもの | 止まるもの |
|---|---|---|
| 関節の「有効」を外す | hub / addr / サーボ ch | その軸の AS5600・INA・PWM |
| 右足の「有効」を外す | FootRoute | 20 Hz の足圧読み |
| PWM チェック（out） | 有効な軸だけ意味がある | その軸のパルス |
| アドレスを 0 にする | 経路そのものを未割当にする | 読まない（有効でも） |

両方オフなら、そのデバイスは I2C に出ません。イベントの `i2c skip jointN (disabled)` は有効マスクです。`AS5600 give up` は有効なのに応答が無いときです。未配線の INA を有効のままにすると、毎周期リトライしてエラーが増えます。

机上の対象が ch0 なら、関節 0 はオン、1〜7 と足はオフ、が典型です。`jen=0x01` がそれです。`0xFE` は逆（0 だけオフ）なので、チェックが戻ったように見えます。

## ボードへ送る手順

1. 使わない軸の「有効」を外す。経路の数字はいじらない
2. **ボードへ送信**（ProfPut）。末尾 2 バイトがマスク。ver 13 未満は無視される
3. ファームは RAM に載せ、NVS の `jprof/en` に 2 バイト書く。旧キー `jen` / `fen` も互換で残す
4. **読み戻しが成功してから** ProfOk を返す（ver 13）。UI の保持はこれ以降でよい
5. 必要なら電源を入れ直して、HELLO 後も同じマスクか見る

「ボードから読む」は RAM 上のプロファイルです。フラッシュに残ったかは NVS タブの `en`（または HELLO 後もチェックが戻らないこと）で見ます。

保存中に COM が落ちると、新規キーの commit が死にます。ver 13 は USB リセットを抑え、Python は DTR を下げます。それでもダンプの最中に HELLO が来たら、その書き込みは疑ってください。

## NVS タブの空欄

| 見え方 | 意味 |
|---|---|
| 灰色の行で値が空 | ファームが知っている名前だが、フラッシュにまだ無い（ゴースト） |
| `en` が無い | 一度も ver 12 以降で保存していない。旧ボードは `jen` だけ |
| 読み取り開始のあと HELLO | ダンプが CDC を殺した。未読取。キーが空とは限らない |
| `nvs.ok` のあと空 | 本当にそのキーは無い |

「ボードから読む」でプロファイルが埋まっても、NVS タブが空のまま、ということはあります。前者は RAM、後者はダンプ完了待ちです。

`cal/mx0` のようなマップは 1 本で数百バイトあります。一覧はキーごとに値まで載せるので、校正済みボードほど重いです。

## 消してよいもの

USB の NVS 消去は `cal` と `jprof` だけ受けます。`jprof` を消した直後、ファームは既定経路を書き戻します。app 区画（プログラム）は消えません。工場出荷に戻すなら erase フラッシュです。
