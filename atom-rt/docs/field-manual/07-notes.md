# 現場メモ

ログと画面の読み方、次に直すと楽なことです。症状から入ります。

## イベントの読み方

ドックは新しい行が下です。一時停止してからスクロールします。接続し直すと最大 5000 行入ります。それより古いものはデーモン側で捨てています。

| 行の気配 | まず疑うこと |
|---|---|
| `i2c skip jointN (disabled)` が周期で増える | 有効オフは正常。消したいならそれでよい |
| `INA226` / `AS5600` 失敗が 20 Hz で増える | 有効なのにデバイスが無い。机ならチェックを外す |
| `AS5600 give up` | 磁石・配線・PaHub の CH。有効はオンのまま |
| 有効を外した直後も同じ失敗 | ボードへ未送信。RAM が古い |
| 送信したのにチェックが戻る | ファーム ver 12 未満、または PUT からマスクが落ちている |
| チェックは残るが NVS に `en` が無い | 保存が commit 前に CDC 切断。ver 13 を焼く |
| `NVS 読み取り開始` の直後 HELLO | ダンプが COM を殺した。キーが空とは限らない |
| HELLO が数秒おき | NVS タブの自動一覧が再接続と輪になっている |
| `jen=0xFE` | 関節 0 だけオフ。机の ch0 なら逆 |

I2C エラー増分がステータスバーで赤点滅しているときは、トポロジと有効を先に見ます。SCAN は実在するアドレスだけ返します。プロファイルの既定値は「機体の典型」で、机の配線そのものではありません。

## よくある取り違え

- **Hub が ATOM に直接 USB している。** していません。Python が COM を持ち、Hub は JSON です
- **空の NVS 行は消えたデータ。** 期待キーのゴーストです。ダンプ完了後に本当に無いか判定します
- **「ボードから読む」はフラッシュ。** RAM です。再起動後も同じか、`en` があるかでフラッシュを見ます
- **115200 が遅いからダンプが落ちる。** CDC では飾りです。落ちる原因はフラッシュキャッシュと同居です
- **バイト列は ASCII コマンド。** `AA 55` で始まるフレームです。モニタの文字化けは仕様です
- **机上用に別スケッチが要る。** Lab モードと有効マスクです。焼き直しはプロトコルを上げるときだけです
- **PWM オフと有効オフは同じ。** 違います。有効オフはセンサも叩きません

## 作業の順番（机上 1 サーボ）

1. `lab_debug.py` を上げ、Hub で `/atom-bench` を開く
2. USB ver が 14 以上か、ステータスバーで見る
3. SCAN して、刺さっているものだけ緑になるのを見る
4. プロファイルで対象軸だけ有効。他はオフ。経路は消さない
5. ボードへ送信。イベントで ProfOk。再読み込みしてもチェックが残るか見る
6. NVS タブは、保存の確認が必要なときだけ開く。落ちたらタブを閉じて HELLO が止まるのを待つ
7. 校正は PC 掃引。JSON を `data/cal_map_*.json` に残す

## 次に直すと効くこと

コードにはまだ入っていません。ここに書いておくと、同じ穴を踏まずに済みます。

1. **NVS 一覧は名前・型・サイズだけ。** 値はキーを指定して取る。Hub は必要な行だけ読む
2. **ダンプ中はテレメトリを止める。** MapGet と同じ。パイプを一人で使う
3. **NVS タブの自動 `nvs_list` を、再接続のたびに撃たない。** 手動、または完了するまでロック
4. **校正マップの正本は PC の JSON。** ボードは実行用キャッシュ。巨大 blob を毎回 CDC で吸い上げない
5. **ATOM S3R** では WS2812 を LP5562 に替える。PSRAM はマップ展開の余裕になるが、USB の層は同じ
6. **政策（RL）** は `selectAction` の差し替え。USB と NVS はその前に安定させる
