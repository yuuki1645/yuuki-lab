## いまの段階

最終目標は、この学習で等身大の脚を動かすこと。今は自由歩行の前の準備で、実機で見るものは次の二つ。

- Isaac Lab と実機で、方策が見る量の分布がどう違うか。
- 実機の計測が、シミュの 30 Hz のように揃っていないこと。欠測、飛び、値の古さ。

歩行の報酬や `model_2200` は、この段階では変えない。吊りベルトは付けたまま。最初の前進指令は 0。

## 判断

1. 比べる単位は実験である。直立、1 関節、体重移動、浅いしゃがみ。実験開始から何秒後、という時刻同士は比べない。実機は初期姿勢、センサ、計測の遅れ、吊り方で、開始直後からシミュのその時刻とは別の状態になる。時刻を揃えた比較は、直立の分布とセンサの旗が安定してから。
2. 比べる値は、方策が見た 38 個そのもの。画面の度から逆算しない。平均とばらつきは、旗が有効で、安全が働いていない周期だけ。欠測率と飛び率は、それとは別に出す。
3. AS5600 は欠測・大きなずれ・揺れがあり得る。SM105BL は安定しているが、同じ旗を付ける。壊れた値を指令角で埋めない。埋めると、見たい差が消える。飛びは欠測と同じくネットへ入れない。揺れは旗だけにして、ネットは回す。
4. 足裏は、足が体重を受けている周期だけ平均に入れる。吊っているあいだの 0 kg を、シミュの接地と比べない。
5. 波形は、選んだ側の 1 本だけを見る。欠測と飛びの区間は線でつながない。周期の遅れと、値が何ミリ秒前の計測かは、実機の記録の質として見る。シミュの波形の位置合わせには使わない。
6. 危険な目標は、CoreS3 が CAN と RS485 に書く前に止める。サブ PC が気づいてからでは、その周期の指令はもう出ている。USB の往復が方策の周期より遅い、というのが推論を腰に置いた理由と同じ。
7. 欠測や飛びのとき、直立へ一瞬で飛ばさない。今の目標から、サーボの最高速度以内で戻す。トルクは残す。脱力は、人が全停止を押したときだけ。方策ボタンを切ったときの直立への復帰は、これまでどおりトルク付き。

## 方策

- 学習 `2026-11-27_14-01-29_stand_half` の `model_2200`。重みは `core-rt/src/policy_weights.hpp`。このヘッダは生成物で、手で直さない。
- 推論は腰の CoreS3。入力 38、隠れ 128 と 64、ELU、出力 10。観測の正規化あり。出すのは平均で、ガウス分布からは引かない。批評家は載せない。
- 周期は約 33 ms。腰も `can-leg` も合わせてある。机上の `rt-usb` は 50 ms のまま。
- スイッチは実機テレメトリの「方策」ボタン（USB `0x92`）。起動時は切。ボタンは前進 0 を送る。入っているあいだ、関節のバーは動かない。
- 実機のサーボは自分の位置ループを持つ。学習の Kp=80、Kd=2 をサーボへ書かない。
- 入れる前に、画面の重力 z が約 −1 であることを見る。軸が違うときは `core-rt/src/bmi270_waist.cpp` の表だけを直す。カゴへの取り付けは未計測で、初期値はチップ軸をそのまま体軸とみなしている。

## 記録は二つある

HELLO（USB ver 15）から USB を抜くまで、`lab_debug.py` がセンサ・指令・イベントと、方策の 1 周期を自動で残す。保存先はユーザーの `storage.yaml`。形式は `core_take_v2`。実験名は無い。机上の ver 14 では始まらない。方策が見た 38 個と、頭打ち前のネットの出力は `policy/` にある。関節の並びは同じフォルダの `context.json`。

画面の「記録開始」から「記録停止」までが本記録で、`atom-rt/data/recordings/<id>/` に残る。

- `frames.jsonl` は、画面に出しているテレメトリ。度、電流、足裏、周期。
- `policy_trace.jsonl` は、方策の 1 周期。分布の比較が読むのはこちら。USB `0x1A`。

シミュの再生は、方策ステップごとに同じ形を `atom-rt/data/policy_traces/sim/` へ書く。画面へ出す 20 Hz ではなく、方策のステップである。観測は `obs_buf` の policy そのもので、画面の度からは作らない。実験名は、本記録を始めた名前か、Hub「分布の比較」のボタンが書く `policy_traces/next_name.txt`。

`lab_debug.py`（`:8794`）と `isaac_hub_bridge.py`（`:8795`、Isaac とは `:8796`）は同時に動かさない。

## 安全のふるまい

判定の定数は `core-rt/src/walk_policy.cpp`。ここへ写さない。

- 目標の 1 周期の変化は、そのサーボの最高速度まで。
- 計測が 1 周期でその速度を超えたら飛び。欠測と同じくネットを回さず、直立へ速度制限つきで戻す。
- 直近の窓で標準偏差が大きい軸は揺れ。分布の平均からは外し、ネットは回す。
- 前進 0 のまま、目標か計測が直立の包絡の外に居続けると、ネットを止めて直立へ戻す。待ちのあいだも、目標はその包絡の外へ出さない。
- 戻しているあいだ、計測がさらに外へ逃げる周期が続くと、目標をその場で固定する。
- 安全が働いた周期は、平均に入れない。働いた割合は、実機の記録の質として画面に出る。
- 過電流のあとは、人が方策を入れ直すまで出力を戻さない。

## サブ PC でやること

1. この作業ツリーを、コミットしてから取る。`policy_weights.hpp` を忘れない。
2. `core-rt` を PlatformIO でビルドし、腰の CoreS3 へ書く。メイン PC にはビルド環境が無く、コンパイルしていない。メイン PC から書き込まない。
3. `lab_debug.py` を起動し直す。新しい Python の受信は、動いているプロセスには入らない。
4. 実機テレメトリで実験名を選び、記録を開始する。方策は、重力 z が約 −1 なのを見てから、前進 0 で入れる。
5. シミュの分布は、メイン PC で再生をやり直したあとにできる。この記録を入れる前に閉じた `model_2200` の再生には、このファイルは無い。
